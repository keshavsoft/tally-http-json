TDL Walk versus JavaScript flattening

Two operations can produce flat rows, but they run at different stages.

QuestionTDL WalkJavaScript flattening
Where does it run?Inside Tally while evaluating the collection definition.In the application after JSON has been returned.
What does it traverse?Tally's collection/object hierarchy.Arrays and objects in the returned JSON value.
Can it access Tally methods directly?Yes, according to the current object context and TDL definition.No. It can only use values present in the JSON it receives.
How is parent context retained?Use the appropriate source fields and computed methods in the TDL collection.Copy selected parent properties into each child output row.
Best role in this designExpose the necessary data and traverse Tally's nested structures.Provide reusable, configurable reshaping for application needs.

Why keep both ideas separate?

If Tally can expose parent and child values directly in a useful flat collection, that can reduce the amount of nesting sent over HTTP. A generic JavaScript function is still useful when the input is already nested, when different paths are needed, or when a caller wants a different output shape.

The JavaScript function should not assume it can reconstruct omitted parent values. If the input JSON does not contain the required parent information, the function needs another source or must report that the information is unavailable.
