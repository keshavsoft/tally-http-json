How do we send a TDL-backed HTTP JSON request?

Launch pad 2 — request envelope, company settings, definitions, and response.

The simple workflow

Our test environment sends HTTP requests to Tally at http://localhost:9000. The request headers select an export operation. The JSON body supplies static variables and, when needed, TDL definitions.

Step 1 — understand the request envelope

POST http://localhost:9000
Content-Type: application/json
version: 1
tallyrequest: Export
type: Collection
id: KSReceiptLedgerEntryProbe
  • tallyrequest: Export asks Tally to export data.
  • type: Collection selects a collection export.
  • id names the collection being requested in this example.

Step 2 — supply company and export format

{
  "static_variables": [
    {"name": "svExportFormat", "value": "jsonex"},
    {"name": "svCurrentCompany", "value": "mani9"}
  ]
}

These are the settings used in our working environment: JSONEx output and company mani9.

Step 3 — define the collection in TDL

Our request includes a tdlmessage array containing definitions. Each definition has metadata (name and type) and attributes describing the collection.

{
  "metadata": {
    "name": "KSReceiptLedgerEntryProbe",
    "type": "Collection",
    "ismodify": false
  },
  "attributes": [
    {"Source Collection": "KSReceiptVoucherSource"},
    {"Walk": "AllLedgerEntries"},
    {"Source Fetch": "Date,VoucherNumber"},
    {"Fetch": "LedgerName"},
    {"Fetch": "Amount"},
    {"Fetch": "IsDeemedPositive"},
    {"Compute": "ParentVoucherNumber: $VoucherNumber"},
    {"Compute": "ParentVoucherDate: $Date"}
  ]
}
Scope: this is the central definition, not a complete standalone HTTP request. The complete tested request also defines KSReceiptVoucherSource as a Receipt-voucher collection and includes the headers and static variables above.

What happened in our actual test?

The response included ledger-entry records and the computed fields parentvouchernumber and parentvoucherdate. One screenshot showed voucher number 471 and date 20261017. That confirms the tested collection exposed those values alongside a ledger entry.

What to check

  1. Did Tally return a successful response?
  2. Are the expected collection records present?
  3. Are the selected fields present on each record?
  4. Do parent values match the voucher that owns the entry?
Learning goal: first learn the request and response. Then learn how TDL defines data traversal. Avoid designing the final JSON shape too early.
