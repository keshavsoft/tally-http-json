What does flattening mean?

Launch pad 3 — parent vouchers, child ledger entries, and preserving context.

Flattening in one sentence

Flattening turns nested child records into a sequence of rows, while carrying along the parent information needed to understand each row.

Before flattening: nested data

[
  {
    "Date": "20261017",
    "VoucherNumber": "471",
    "AllLedgerEntries": [
      {"LedgerName": "Cash", "Amount": "100.00"},
      {"LedgerName": "Customer A", "Amount": "-100.00"}
    ]
  }
]

The voucher is one parent object. Its AllLedgerEntries value contains multiple child objects.

After flattening: one row per child entry

[
  {
    "ParentVoucherNumber": "471",
    "ParentVoucherDate": "20261017",
    "LedgerName": "Cash",
    "Amount": "100.00"
  },
  {
    "ParentVoucherNumber": "471",
    "ParentVoucherDate": "20261017",
    "LedgerName": "Customer A",
    "Amount": "-100.00"
  }
]

This is an illustrative shape to explain the concept, not a verbatim copy of Tally's complete JSONEx response.

What TDL does in our experiment

Source Collection identifies the voucher collection to start from.

Walk: AllLedgerEntries traverses the child ledger-entry collection for each voucher.

Source Fetch: Date,VoucherNumber makes the source voucher fields available during traversal.

Fetch requests child fields such as LedgerName, Amount, and IsDeemedPositive.

Compute defines values such as ParentVoucherNumber and ParentVoucherDate on the resulting rows.

Why parent context matters

If we flatten entries but discard the voucher number and date, a ledger-entry row may no longer tell us which voucher it came from. Carrying parent fields makes each row independently understandable and allows later grouping or filtering.

Where JavaScript comes in

Our next layer can accept JSON and a path to the child collection, then produce a flat array. A future call might conceptually look like:

flattenByPath(data, "AllLedgerEntries")

The exact function contract is not defined yet. Before implementing it, decide whether the path is relative to each voucher, how parent fields are selected, and what to do if the path is missing.

Do not mix the two operations. TDL's Walk traverses Tally's collection while Tally builds the response. A JavaScript flatten function traverses JSON that has already been returned. They are related ideas, but run at different stages.

Small checklist

  • Identify the parent collection.
  • Identify the child collection/path to flatten.
  • Choose which parent values must travel with each child.
  • Choose which child fields to retain.
  • Verify each flattened row still belongs to the correct parent.
