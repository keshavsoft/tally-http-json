What is TDL, and why do we need it?

Launch pad 1 — the simplest mental model for Tally data retrieval.

The short story

TDL means Tally Definition Language. It is used to describe and customize Tally's data structures, collections, reports, forms, fields, and related behavior.

Think of Tally as the system that owns the business data. TDL tells Tally what data to gather and how to traverse or present it. An HTTP JSON request is one way to ask Tally to perform that work and return a response.

Why do we need TDL?

  • Describe a collection: for example, Receipt vouchers.
  • Choose fields: for example, Date, VoucherNumber, PartyLedgerName, Amount.
  • Traverse nested data: for example, ledger entries inside each voucher.
  • Add computed methods: for example, attaching a parent voucher number to each walked ledger entry.
Keep responsibilities clear. TDL works inside Tally, where the business objects and relationships exist. JavaScript can consume the response and transform it for an application.

Three terms to remember

Object

A business record or object, such as one voucher or one ledger.

Collection

A set of objects Tally can retrieve or iterate over, such as Receipt vouchers.

Method / field

A value available on an object, such as Date, VoucherNumber, or Amount. TDL can fetch existing methods or define computed ones.

What TDL is not

TDL is not the JSON itself, and it is not the JavaScript flattening function. JSON is the transport/data representation in our HTTP workflow. TDL defines Tally-side retrieval and traversal; JavaScript handles application-side processing.

Remember: TDL tells Tally what to retrieve and how to traverse it; JavaScript can transform the returned data into the shape our application needs.
