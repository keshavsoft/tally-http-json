Example: flatten ledger entries inside Tally

Read the tested collection that walks AllLedgerEntries and preserves voucher context.

Observed working result The repository file http/asJson/receipt/flat/gridRowsMoreFields.http contains this definition.

{
  "metadata": {
    "name": "KSReceiptLedgerEntryProbe",
    "type": "Collection",
    "ismodify": false
  },
  "attributes": [
    {"Source Collection": "KSReceiptVoucherSource"},
    {"Walk": "AllLedgerEntries"},
    {"Source Fetch": "Date,VoucherNumber"},
    {"Fetch": "LedgerName"},
    {"Fetch": "Amount"},
    {"Fetch": "IsDeemedPositive"},
    {"Compute": "ParentVoucherNumber: $VoucherNumber"},
    {"Compute": "ParentVoucherDate: $Date"}
  ]
}

The request also defines KSReceiptVoucherSource as a Receipt-voucher collection and fetches Date and VoucherNumber.

Why it matters

The response screenshot shows each ledger-entry object with its own entry fields and the computed parentvouchernumber and parentvoucherdate. For the displayed example, the values were voucher number 471 and date 20261017.

Precision: this confirms the behavior in the user's tested setup. Validate the output against the target Tally version and company before depending on it in production.
