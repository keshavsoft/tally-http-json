Designing a path-based JavaScript flatten API

Decisions to make before implementing a reusable flattening function.

Documentation home / Advanced

Proposed conceptual call

flattenByPath(data, {
  path: "AllLedgerEntries",
  parentFields: ["Date", "VoucherNumber"],
  prefixParentFields: true
});

This is a design sketch, not an implemented API or an agreed final contract.

Questions the contract must answer

  1. Input root: can the input be an object, an array, or both?
  2. Path meaning: is the path relative to each parent record or absolute from the root?
  3. Nested path syntax: how will deeper paths be represented?
  4. Parent field selection: which fields should be copied to each child row?
  5. Collision behavior: what if the child already has a field named Date?
  6. Missing path: return an empty array, preserve the original record, or raise a descriptive error?
  7. Multiple levels: does one call flatten one collection or multiple nested levels?
  8. Immutability: should the function avoid mutating the input? Prefer yes.
  9. Value preservation: should JSONEx wrappers remain intact or be unwrapped? Keep this separate unless explicitly required.

Suggested first version boundary

Start with one nested array path and explicitly selected parent fields. Do not add arbitrary mapping, filtering, aggregation, renaming, or recursive flattening until the basic behavior is tested.

Design principle: make the caller's intent visible in the configuration. A reader should be able to tell which collection is flattened and which parent values are carried into each output row.
