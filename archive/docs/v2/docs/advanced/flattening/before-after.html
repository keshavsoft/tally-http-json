Flattening: a worked before-and-after example

Use one voucher with two ledger entries to see exactly what changes.

Home Users Learners Developers Advanced Examples Reference
Documentation home / Advanced

Input: nested voucher data

[
  {
    "Date": "20261017",
    "VoucherNumber": "471",
    "VoucherTypeName": "Receipt",
    "AllLedgerEntries": [
      {
        "LedgerName": "Cash",
        "IsDeemedPositive": false,
        "Amount": "100.00"
      },
      {
        "LedgerName": "Customer A",
        "IsDeemedPositive": true,
        "Amount": "-100.00"
      }
    ]
  }
]

One array item represents one voucher. Inside it is an array of two ledger entries.

Operation: flatten AllLedgerEntries

  1. Read the parent voucher's Date and VoucherNumber.
  2. Visit each object in AllLedgerEntries.
  3. Make one output row for each child object.
  4. Copy the parent date and number into each row.
  5. Copy the chosen child fields into that row.

Output: flat ledger-entry rows

[
  {
    "ParentVoucherNumber": "471",
    "ParentVoucherDate": "20261017",
    "LedgerName": "Cash",
    "IsDeemedPositive": false,
    "Amount": "100.00"
  },
  {
    "ParentVoucherNumber": "471",
    "ParentVoucherDate": "20261017",
    "LedgerName": "Customer A",
    "IsDeemedPositive": true,
    "Amount": "-100.00"
  }
]

What changed?

AspectBeforeAfter
Top-level rowsOne voucherTwo ledger-entry rows
Entry locationNested in AllLedgerEntriesEach entry is a top-level row
Parent identityStored once on voucherRepeated on every child row
Entry fieldsInside each child objectKept on corresponding row
Not a data correction: flattening should not silently change amount signs, dates, or business meaning. It reorganizes structure. Any renaming or value conversion should be a separate, explicit transformation.

Multiple vouchers

If there are three vouchers with two, three, and one ledger entries, respectively, the flattened output contains six rows. Every row should retain the correct parent identity for its own voucher.
