Parent context: keep each row traceable

Why parent fields matter when child objects become independent rows.

Home Users Learners Developers Advanced Examples Reference
Documentation home / Advanced

The problem

A ledger entry might contain a ledger name and an amount but not the voucher number or date. Once moved out of its nested parent array, the entry may lose the context needed to interpret it.

The solution

Carry selected parent values into each child row. In the current experiment, those values are the voucher number and date.

{
  "ParentVoucherNumber": "471",
  "ParentVoucherDate": "20261017",
  "LedgerName": "Cash",
  "Amount": "100.00"
}

Choosing parent fields

  • Choose stable identifiers whenever possible.
  • Include descriptive fields only when useful to downstream consumers.
  • Be explicit about whether a value comes from the parent or the child.
  • Keep original values unless a separate conversion is requested.

Do not confuse parent fields with aggregation

Repeating a voucher number on each entry does not combine or sum the entries. Aggregation is a separate operation with separate rules.
