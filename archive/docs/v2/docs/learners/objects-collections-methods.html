Parent and child

For the receipt example, a voucher is the parent. Its ledger entries are child objects. A single voucher can contain more than one ledger entry.

Receipt Voucher
├── Date
├── VoucherNumber
└── AllLedgerEntries
    ├── Ledger Entry: Cash
    │   └── Amount
    └── Ledger Entry: Customer
        └── Amount

Why the distinction matters

Date belongs to the voucher context, while LedgerName and Amount belong to each ledger-entry context. When traversing into the child collection, a definition must intentionally retain the parent values that each output row will need.

The diagram is conceptual. Tally's actual object hierarchy and the exact methods available depend on the object and TDL definition being used.
